# REVEN Benchmark

> ⚠️ **Important**: All benchmark results use **synthetic data**. Calibration profiles are generated by `build_calibration_profile()` in `backend/reven/calibration_profiles.py` and are **not** derived from actual KKBOX churn dataset analysis.

---

## Methodology

The benchmark in `backend/reven/benchmark.py` performs a fair, per-customer comparison between:

1. **REVEN policy** — run the full decision pipeline for each customer
2. **Do-nothing baseline** — simulate what happens with no intervention

### Input

- **Population**: 10,000 synthetic customers generated by `customer_generator.generate_population(count=10_000, seed=42)`
- **Events**: 30-day observation window, generated by `event_engine.generate_events()`, seed=42
- **Per-customer outcome**: Both REVEN and baseline use the same seed (`seed + customer_index`) for outcome simulation — ensuring deterministic, reproducible results

### Seed

- `seed=42` for population generation
- `seed=42` for event generation
- `seed + index` for per-customer outcome simulation

### What Is Compared

For each of the 10,000 customers:
1. Run REVEN policy → get `RevenueDecision` + simulated `Outcome`
2. Run baseline (no intervention) → get simulated `Outcome`
3. Compute incremental revenue = REVEN outcome net revenue − baseline net revenue

### Metrics

| Metric | Formula |
|---|---|
| **Intervention rate** | `decisions_intervened / total_customers` |
| **REVEN net revenue** | `Σ(outcome.net_revenue)` over all REVEN customers |
| **Baseline revenue** | `Σ(outcome.net_revenue)` over all baseline customers |
| **Intervention cost** | `Σ(outcome.intervention_cost)` over all REVEN customers |
| **Incremental net revenue** | REVEN net revenue − baseline revenue |
| **ROI** | `incremental_net_revenue / intervention_cost` |

## Policy Thresholds

REVEN's policy engine applies these gates:

```
MINIMUM_UPLIFT = 0.05          # 5% minimum incremental lift
MINIMUM_NET_VALUE = 5.0        # ₹5 minimum expected incremental net revenue
MINIMUM_AUTONOMOUS_RISK_SCORE = 30.0
MINIMUM_RENEWAL_REMINDER_RISK_SCORE = 40.0
MINIMUM_PERSONALIZED_OFFER_RISK_SCORE = 40.0
MINIMUM_DISCOUNT_RISK_SCORE = 45.0
MINIMUM_PLAN_CHANGE_RISK_SCORE = 55.0
MINIMUM_CANCELLATION_SAVE_RISK_SCORE = 70.0
```

These thresholds control the **intervention rate**. REVEN deliberately chooses NO_ACTION for most customers because most customers are not at sufficient risk to justify intervention costs.

## Expected Results (Synthetic Data)

> ⚠️ These are approximate ranges based on code review, not a fresh run.

```
Population:       10,000 synthetic customers
Interventions:    ~1,500–2,500 (varies by seed/risk distribution)
No action:        ~7,500–8,500
Baseline revenue: ~₹2,000,000–2,500,000 (depends on renewal probability)
REVEN revenue:    higher than baseline
ROI:              positive (REVEN only intervenes when profitable)
```

**Key insight**: The intervention rate is intentionally low. REVEN is designed to have a **high ROI** (return on intervention spend), not a high intervention rate. Most customers don't need intervention — the economic value comes from correctly identifying the few who benefit and not wasting money on those who don't.

## Limitations

1. **Synthetic customers** — not real customer data; risk distributions may not match production
2. **Synthetic events** — generated by `event_engine.py` with rule-based logic; not from real behavioral data
3. **Synthetic calibration** — `build_calibration_profile()` uses hardcoded values, not actual KKBOX analysis
4. **Seeded stochastic** — outcomes are reproducible (good for testing) but may not reflect real-world variance
5. **No holdout** — the benchmark compares REVEN vs baseline on the same customers, not a randomized controlled trial

## Calibration Pipeline

The synthetic calibration pipeline:

```
1. customer_generator.generate_population(count=10_000, seed=42)
      → 10,000 Customer + Subscription objects with randomized attributes
      → Tenure, plan, price, signup date

2. event_engine.generate_events(customers, subscriptions, seed=42)
      → Generates risk events: payment_failure, cancellation_requested,
        engagement_declining, inactive, renewal_due
      → Each event has severity and metadata

3. calibration_profiles.build_calibration_profile(customer, events)
      → Hardcoded probability values per intervention type
      → NOT derived from actual KKBOX data analysis

4. outcome_engine.simulate_outcome(...)
      → Seeded RNG for stochastic outcomes
      → Returns Outcome with recovery/renewal/churn flags
```

Real calibration from KKBOX data is **not implemented**. The synthetic profiles are placeholders for a future data pipeline.
